# 手机竖屏入口缺失：排查与修复

用户确认：竖屏打开后找不到横屏入口。

## 修复前的证据

`game.js` 的全屏处理只调用 requestFullscreen，未请求屏幕方向，入口也只有符号。现有 mobile_check 分别创建竖屏与横屏页面，没有覆盖同一页面从竖屏进入横屏。

| 排序 | 假设 | 验证方式与结果 |
| --- | --- | --- |
| 1 | 缺少明确且实际可用的横屏入口 | 源码确认只有“全屏显示”。新增竖屏入口回归测试，修复前无法找到“横屏玩”按钮。 |
| 2 | 浏览器不支持全屏或方向锁定，导致点击后仍竖屏 | 让 API 不可用，检查页面仍能提供横向画布和可点击按钮。W3C 明确允许方向锁定以 NotSupportedError 拒绝，不能把 API 可用当作前提。 |
| 3 | 旋转后画布宽高取自变换后的矩形，导致渲染比例或触屏布局错误 | 在同一页面进入横屏、改变实际视口、退出并重复进入；校验未变换的画布布局宽高、屏幕内按钮及真实多点触控。 |

## 修复范围

手机提供“横屏玩”入口和始终可用的退出入口。优先尝试浏览器全屏与 landscape 方向锁定；无法使用这些能力时，以页面旋转保持横向游戏布局。物理、关卡、角色与成绩不变；桌面保留全屏行为。

依据：https://www.w3.org/TR/screen-orientation/

真实手机的系统方向锁定、浏览器地址栏和安全区仍需实体设备验收；自动化覆盖 Chromium 的模拟视口与不支持 API 的路径。当前环境未安装 WebKit，尚未对 Safari 内核或实体 iPhone 验收。

## 本机验证结果

- 新增入口回归测试修复前失败，修复后通过。
- 四项横屏专项检查通过：竖屏入口与真实多点触控；同页旋转/退出/重入；原生接口拒绝时的页面横屏；桌面原生全屏进入和退出。
- 36 项机制测试、10 项通关演出专项检查、两种陷阱真实键盘检查均通过。
- 最终完整六关键盘通关、桌面/手机横竖屏、离线资源、存档和暂停检查通过；控制台与资源错误均为零。
- 原完整自动驾驶测试曾在群岛最后缺口失败；单关诊断和带输入记录的完整复测通过，没有修改游戏物理来绕过失败。日志保留在本机 QA 目录。
- 修复前核对，GitHub Pages 线上提交为 43eac74；发布本次修复后手机才能看到“横屏玩”。
